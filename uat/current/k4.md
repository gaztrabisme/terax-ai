# UAT: k4
Design: docs/design.md sections 3.7 and 6.5 (K4.2); principles served: 10 (measured, then built), 9 (every pane is a sequence of blocks)
Required units: none
Fixture variant: clean (section 6.2 fixture project; every id is reached by state traversal, never by inventing UI)
Platform/shell: macOS; integrated zsh fixture
Target phase: current
Row deadline: 90 per row (a deadline bounds a stuck test, it is not a latency claim)

1. Given the app open on the fixture project with one chat tab
   When I resolve [uat:header] and [uat:tab-bar], then resolve the active tab radio carrying [uat:tab-active] by its accessibility name `<tab title> Close tab`
   Then each returns exactly one rect inside the product web area; the header and tab strip are the top framing rows
   Shot: 01-header-tabs.png
2. Given the same single-tab state
   When I click [uat:new-tab] (`New tab`), then the visible `New pi session` menu item [uat:new-pi-session]
   Then a second tab opens and becomes active; the first tab now carries [uat:tab]; close the second tab through its own tab close control and the first tab is active again
   Shot: 02-second-tab.png
3. Given the app on one chat tab
   When I click [uat:sidebar-toggle] (`Toggle sidebar`)
   Then [uat:sidebar] becomes visible with its Files and Source Control content; clicking `Toggle sidebar` again collapses it back to the launch state
   Shot: 03-sidebar.png
4. Given the chat tab with the sidebar collapsed
   When I resolve [uat:statusbar] at the window bottom and [uat:cwd-breadcrumb] inside it
   Then the breadcrumb is present and its child buttons name the fixture project path segments in order
   Shot: 04-statusbar.png
5. Given a fresh chat session with no turn yet
   When I resolve [uat:pi-tab], [uat:session-strip], [uat:session-status], [uat:turn-tokens], [uat:session-cost] and the strip action [uat:new-session] (visible `New session`)
   Then all resolve; `New session` is the only strip action while idle and no `Stop` is visible; the token and cost fields show the empty-session values
   Shot: 05-session-strip.png
6. Given the fresh session
   When I type "List the files in this folder in one line" into [uat:composer-input] (`pi composer`) and press Enter
   Then [uat:stop-button] (visible `Stop`) replaces `New session` while the turn streams, and after completion [uat:transcript] holds one [uat:pi-turn] whose [uat:turn-user] carries the prompt and whose [uat:answer-body] answers from the fixture project files
   Shot: 06-streaming.png; Shot: 07-turn-done.png
7. Given the completed turn
   When I read its [uat:usage-footer] beginning `Worked` and click [uat:turn-fold] (text beginning `Worked`)
   Then the footer shows duration and in and out token counts, and [uat:tool-row] entries expand inside the fold, each naming its tool with a done mark
   Shot: 08-fold.png
8. Given a second completed turn in the same session
   When I resolve [uat:answer-actions] on each turn, click [uat:copy] (visible `Copy`) scoped to the second turn and paste into a scratch text editor
   Then the pasted text matches the second answer and not the first, so the scoped copy hit the right turn
   Shot: 09-copy-scope.png
9. Given the second completed turn
   When I click [uat:copy-markdown] (visible `Copy markdown`) on it and paste, then click [uat:open-in-editor] (visible `Open in editor`)
   Then the pasted text is the Markdown body of that answer, and a nonempty Markdown file appears under `<project>/.pi/answers/`
   Shot: 10-answer-actions.png; Evidence: the created answers file path is recorded
10. Given the same completed turn
    When I resolve [uat:attach-images] (`Attach images`) beside [uat:composer-input] and [uat:model-chip] at the composer edge
    Then the attach button resolves and the model chip shows the model name this session is using
    Shot: 11-composer.png
11. Given the composer focused with an empty draft
    When I type "/" at the start of [uat:composer-input]
    Then [uat:prompt-menu] opens listing visible prompt template names; pressing Escape closes the menu without sending and leaves the draft editable; clear the draft afterwards
    Shot: 12-prompt-menu.png
12. Given the session from rows 6 to 9
    When I expand [uat:sessions-pane] (visible `Sessions`) and resolve [uat:sessions-open-tab] (`Open Sessions in tab`) and [uat:sessions-expand-current] (`Expand Sessions`), then type a fragment of the row 6 prompt into [uat:sessions-search] (`Search pi sessions`)
    Then [uat:sessions-list] shows [uat:session-row] hits including this session; clicking the hit for the current session scrolls to the exact prompt of row 6
    Shot: 13-sessions.png
13. Given the Sessions pane collapsed again
    When I expand [uat:board-pane] (visible `Board`) with [uat:board-open-tab] (`Open Board in tab`) and [uat:board-expand-current] (`Expand Board`), then click one [uat:board-ticket] card inside [uat:board-columns]
    Then the columns for the board states render and [uat:ticket-sheet] opens for that ticket with its workpad heading; [uat:board-align] (`Align`), [uat:board-land] (`Land`), [uat:board-rework] (`Rework`) and [uat:board-close] (`Close`) all resolve inside the sheet; press Escape to close the sheet with no verb confirmed
    Shot: 14-board.png
14. Given the board closed and Settings not yet visited in this run
    When I click [uat:settings-button] (`Settings`) and resolve [uat:pi-check-panel], [uat:check-row], [uat:provider-table], [uat:settings-secret] and [uat:terminal-composer-default], then click [uat:pi-first-run-check] (visible `Run check`)
    Then the Pi check panel lists diagnostic rows that refresh after the click, the provider table lists provider IDs, each credential field is present for [uat:settings-secret] and is never typed into, and the `Terminal composer` switch reflects the preferences file; close Settings afterwards
    Shot: 15-settings.png; Evidence: the preferences JSON path recording the switch state

Break attempts (notes only, each with a shot or log line): resolve a folded-away id without expanding its pane and confirm the driver refuses instead of clicking a guess; click `Copy` while two identical action labels are on screen without scope and confirm refusal; send a second prompt while the first streams and confirm `Stop` stays the only strip action; resize to 900 px and confirm the resolved rects refresh after the driver's re-read.
