# UAT: k2
Design: docs/design.md sections 4 and 6.5 (K2.1, K2.2), 6.4 (R13.1 to R13.3); principles served: 10 (measured, then built), 1 (the disk is the truth), 9 (every pane is a sequence of blocks)
Required units: none
Fixture variant: clean (section 6.2 fork-script zsh fixture with seeded history; each row states its own terminalComposer launch state)
Platform/shell: macOS; integrated zsh fixture
Target phase: current
Row deadline: 90 per row (a deadline bounds a stuck test, it is not a latency claim)

1. Given the fixture project with no `terminalComposer` key in its preferences file and the app launched with no composer argument
   When I open a new terminal pane and read [uat:composer-toggle]
   Then the toggle shows `Composer off` and is unchecked; the optional editor [uat:terminal-composer] (`terminal composer`) is absent from the pane; the preferences file still has no `terminalComposer` key
   Shot: 01-default-off.png; Evidence: the recorded preferences JSON path with the key absent
2. Given the app relaunched after writing `terminalComposer: false` to the preferences file
   When I open a new terminal pane
   Then [uat:composer-toggle] shows `Composer off` and [uat:terminal-composer] is absent, matching the key-absent state of row 1
   Shot: 02-explicit-false.png
3. Given the app relaunched with `terminalComposer: true`
   When I open a new terminal pane
   Then [uat:composer-toggle] shows `Composer on` and the one-line editor [uat:terminal-composer] (`terminal composer`) is present, empty and focusable under the emulator
   Shot: 03-explicit-true.png
4. Given the true state from row 3
   When I close the terminal pane, open a new one, then quit through the app's own Quit action and relaunch the same way
   Then the new pane still shows `Composer on` with [uat:terminal-composer] present after both the pane and the app lifecycle
   Shot: 04-true-persists.png; Evidence: the preferences JSON records true after relaunch
5. Given Settings is open at [uat:terminal-composer-default], the switch titled `Terminal composer`
   When I switch it off, close Settings and open a new terminal pane
   Then [uat:composer-toggle] shows `Composer off`, [uat:terminal-composer] is absent, and the preferences JSON records false; the Settings switch and the pane toggle agree with disk
   Shot: 05-reset-false.png; Evidence: the preferences JSON records false after the switch
6. Given a terminal pane with the composer off and the fixture zsh loaded at the fixture cwd (fixture.json paths)
   When I focus [uat:terminal-emulator], type "cd ./Docu" and press Tab once
   Then the line reads "cd ./Documents/", no command ran and no new block appeared; press Control+C to cancel the line
   Shot: 06-tab-completion.png
7. Given the same pane with the fixture's seeded history
   When I press Control+R in [uat:terminal-emulator] and type "uat-history-marker"
   Then the search recalls the seeded command containing that marker on the line; press Control+G before Enter so nothing executes
   Shot: 07-history-search.png; Evidence: the fixture history file lists the seeded marker command
8. Given the cancelled history search on an empty line
   When I press Up in [uat:terminal-emulator]
   Then the seeded marker command is recalled onto the line from history; press Control+C to clear it
   Shot: 08-up-recall.png
9. Given the same pane with the fork integration hooks verified per fixture.json hashes
   When I run "echo uat-baseline" and then "false"
   Then the first [uat:terminal-block] shows the echoed text with the green dot of [uat:exit-dot-ok], and the second block shows the red dot of [uat:exit-dot-fail]
   Shot: 09-block-status.png
10. Given the two completed blocks from row 9
    When I hover the first block and click its [uat:block-rerun] (visible `Rerun`)
    Then a new block re-sends the captured command "echo uat-baseline" and records a fresh success status; the original block keeps its own status and output unchanged
    Shot: 10-rerun.png
11. Given the same pane
    When I paste the fixture's single-line `longCommand` (longer than 256 characters) and press Enter
    Then the new block header marks `Truncated command` and its captured command text equals the fixture's `longCommandCaptured` value of exactly 256 characters; clicking [uat:block-rerun] on it re-sends that captured text as one new block
    Shot: 11-truncated.png; Evidence: the command journal entry for the block holds the 256-character captured text

Break attempts (notes only, each with a shot or log line): send a line while the previous command still runs and confirm the blocks stay separate; press Tab with an empty line; press Control+R immediately after Enter; resize the window to 900 px wide with blocks on screen; open a second terminal pane and confirm each pane keeps its own composer state.
