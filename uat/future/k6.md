# UAT: k6
Design: docs/design.md sections 3.1 and 6.5 (K6.1 to K6.5); principles served: 3 (tokens are spent on purpose), 10 (measured, then built)
Required units: K6
Fixture variant: clean (section 6.2 fixture; projects A and B for the width rows)
Platform/shell: macOS
Target phase: future
Row deadline: 90 per row (a deadline bounds a stuck test, it is not a latency claim)

1. Given a new project or fresh chat tab opened at first launch
   When I read [uat:mode-strip] at the chat edge
   Then the strip is visible with [uat:board-button], [uat:graph-button] and [uat:sessions-button] in that order; [uat:artifact-button] is absent until the session references a model-written artifact file; no secondary view body is open and the sidebar is collapsed
   Shot: 01-strip-first-launch.png
2. Given the chat tab with no view open
   When I click [uat:sessions-button]
   Then [uat:sessions-popover] opens anchored to the strip and keyboard focus sits in the saved search query
   Shot: 02-sessions-popover.png
3. Given the Sessions popover
   When I click [uat:sessions-expand] (visible `Expand Sessions`)
   Then [uat:sessions-panel] opens as the resizable right-hand column and focus remains in the search query
   Shot: 03-sessions-panel.png
4. Given the Sessions panel
   When I click `Full screen Sessions` ([uat:view-fullscreen])
   Then [uat:sessions-fullscreen] fills the chat tab while the strip stays visible
   Shot: 04-sessions-fullscreen.png
5. Given Sessions fullscreen with returnMode panel recorded
   When I click [uat:view-back] (visible `Back`)
   Then Sessions returns to [uat:sessions-panel] at its remembered width
   Shot: 05-back-to-panel.png
6. Given the Sessions panel
   When I press Escape after focused controls decline it
   Then the view closes to the closed state and focus lands on [uat:sessions-button]; the panel never demotes to a popover
   Shot: 06-escape-closes.png
7. Given the Sessions popover with a query typed into [uat:sessions-search]
   When I click outside the popover
   Then the popover closes, the saved query is retained on disk, and reopening the popover shows the same query
   Shot: 07-query-survives.png; Evidence: the saved-query file or layout record for the query value
8. Given the chat tab with no view open
   When I click [uat:board-button]
   Then [uat:board-panel] opens directly at its saved width (Board never opens a popover); `Full screen Board` ([uat:view-fullscreen]) reaches [uat:board-fullscreen], [uat:view-back] returns to the panel, and Escape closes to the button
   Shot: 08-board-transitions.png
9. Given the chat tab with no view open
   When I click [uat:graph-button]
   Then [uat:graph-panel] opens directly (no popover); `Full screen Graph` ([uat:view-fullscreen]) reaches [uat:graph-fullscreen], [uat:view-back] returns to the panel, and Escape closes to the button
   Shot: 09-graph-transitions.png
10. Given a session whose turn references a model-written artifact file
    When [uat:artifact-button] appears on the strip and I click it
    Then [uat:artifact-panel] opens (no popover); `Full screen Artifact` ([uat:view-fullscreen]) reaches [uat:artifact-fullscreen], [uat:view-back] returns to the panel, and Escape closes to the button
    Shot: 10-artifact-transitions.png
11. Given the Board panel open
    When I click [uat:sessions-button]
    Then Board closes, Sessions opens at its default open mode (the popover), and both transitions persist; clicking [uat:sessions-button] again closes it with focus back on the button
    Shot: 11-switch-views.png; Evidence: the layout record showing both transitions persisted
12. Given project A and project B chat tabs at ample window width
    When I use [uat:panel-resize] (`Resize Board panel`) to set A's Board width to 360 CSS px and B's to 420 CSS px, then switch tabs away and back
    Then each tab keeps its own open Board panel at its own remembered width; closing and reopening tab A restores the tab with Board closed; a full restart restores every chat tab closed; reopening each panel restores its own saved width
    Shot: 12-remembered-widths.png; Evidence: the per-project layout records holding 360 and 420 with visibility reset after restart
13. Given the chat composer with "/" typed and a panel open
    When I press Enter in [uat:prompt-menu], then Escape, then Escape again over the open panel, then focus [uat:terminal-emulator] and press Tab, Enter and Escape
    Then Enter in the menu inserts the template into [uat:composer-input] without sending; the menu's own Escape only dismisses the menu; the panel Escape closes the panel to its strip button; and Tab, Enter and Escape still reach the shell in the terminal
    Shot: 13-event-priority.png
14. Given two tabs where the hidden tab also holds state, and a window that can shrink
    When I capture visible ids with both tabs present, then shrink an open Board panel below the panel-plus-chat minimum and widen the window past it again
    Then the hidden tab contributes no duplicate visible ids; on the shrink the panel collapses to [uat:board-button] and its saved width stays on disk; on widening the panel restores at the remembered width; an explicit close clears the restore marker
    Shot: 14-narrow-window.png; Evidence: the layout record showing the restore marker set and then cleared
15. Given one seeded ticket awaiting a human decision and one running child agent
    When I read the badges on [uat:board-button] and [uat:graph-button] while both views are closed
    Then the Board badge counts the awaiting tickets, the Graph badge counts running children, Sessions shows no badge, and no badge update opens any view by itself
    Shot: 15-badges.png

Break attempts (notes only, each with a shot or log line): resize the window to 900 px wide with a panel open; click strip buttons in fast consecutive succession and confirm at most one view is open afterwards; press Escape while the prompt menu and a panel are both up and confirm the menu dismisses first; enter fullscreen and click another strip button mid-transition; resize to 900 px during fullscreen and confirm Back still lands in a valid state.
