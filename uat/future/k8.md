# UAT: k8
Design: docs/design.md section 4 (block-send-to-chat) and 6.5 (K8.1); principles served: 9 (every pane is a sequence of blocks), 1 (the disk is the truth)
Required units: K8
Fixture variant: clean (section 6.2 fixture project with the zsh fixture terminal)
Platform/shell: macOS; integrated zsh fixture
Target phase: future
Row deadline: 90 per row (a deadline bounds a stuck test, it is not a latency claim)

1. Given a completed terminal block and a chat draft that already holds text
   When I hover that block and click its [uat:block-send-to-chat] (visible `Send to chat`)
   Then the chat composer draft gains the quoted command and output below the existing text, the composer receives focus, and nothing is sent: no new user block appears and [uat:composer-input] holds the combined draft
   Shot: 01-send-to-chat.png
2. Given the combined draft from row 1
   When I quit through the app's own Quit action and relaunch the same project
   Then the chat draft still holds the original text plus the quotation, ready to edit and send by hand
   Shot: 02-draft-survives-restart.png; Evidence: the draft file under `<project>/.pi/drafts/` containing both parts
3. Given the transferred quotation visible in [uat:composer-input]
   When I read the draft record for that quotation
   Then it names the source block ID, the terminal source path and the file hash, and the terminal still owns its own copy of the command output
   Shot: none; Evidence: the draft record's source block id, path and hash fields, and the unchanged terminal journal entry
4. Given a chat composer with an empty draft
   When I click [uat:block-send-to-chat] on a completed block
   Then the draft contains only the new quotation, remains unsent, and a second transfer appends a second quotation without dropping the first
   Shot: 03-empty-draft-then-second.png

Break attempts (notes only, each with a shot or log line): transfer while the composer holds unsent text with trailing whitespace and confirm it is preserved; transfer the same block twice and confirm two quotations; transfer during a streaming answer and confirm the stream is untouched.
